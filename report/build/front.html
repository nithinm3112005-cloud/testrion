ABSTRACT

Machine-learning models fail differently from ordinary software. A model can run without a single error and still make inaccurate predictions, crash on missing or unusual inputs, treat groups of people unequally, or silently degrade as the data changes. Conventional unit tests cannot detect these failures at scale. This project presents Testrion, a full-stack platform for automated software testing and problem solving of machine-learning models.

Testrion accepts any tabular CSV dataset, detects whether the task is classification or regression, trains one of twelve scikit-learn models and executes up to 24 automated tests in five categories: data quality, model performance, robustness, reliability, and fairness with data-slice testing. The robustness tests include generated edge-case inputs, adversarial perturbation search and metamorphic relations. A deployment gate approves or blocks a release using hold-out accuracy (R² for regression) of at least 85%, a demographic parity difference below 10%, worst-class recall, absence of target leakage and reproducible predictions. When tests fail, an Auto-fix engine repairs the data pipeline, tunes hyper-parameters, searches alternative algorithms and re-runs the complete suite so that the improvement is verified. The hold-out test set is never used to fit, tune or select a model.

The system is implemented with a React front-end, a FastAPI back-end, SQLite storage, a live drift-monitoring service, a Streamlit interface and a GitHub Actions workflow. It was evaluated on five built-in and six uploaded demonstration datasets. Auto-fix raised the quality score of the house-price model from 75.0 to 97.1 and changed the deployment decision from blocked to approved; the loan-approval dataset improved from 64.8 to 97.7 after protected attributes that caused a parity gap were removed. Measured on one Apple M5 machine, the full suite processed one million records in 22 seconds with a linear model, one hundred models were tested concurrently in 41 seconds, and drift was detected in 11 milliseconds. These findings apply to the datasets and configuration tested; most datasets are synthetic, and the work does not claim that passing the gate guarantees correct behaviour in production.

Keywords: Machine learning testing, automated testing, deployment gate, fairness testing, data drift, metamorphic testing, automated problem solving, MLOps.
